# コンテスト作業・ルール管理（1.00 開発途中版）

2026-09-11。本ZIPはこれまでの全ソースを含む累積版です。

## 実装済み

コンテストメニューには「コンテスト提出ログ作成」「コンテストルール管理・編集」「Cabrillo出力テンプレート管理・編集」を直接並べます。3項目とも有効です。

作業画面は独立した段階1～5です。

1. JARL R1.0 / R2.1 / Cabrillo / zLog令和版CSVの形式選択。
2. 自局の候補検索、サフィックスを区別したログ選択、JSTの12桁日時範囲（終了分を含む）、RMKS部分一致。ログの再読込。
3. 送受ナンバーの入力、共通送信番号を空欄だけに設定、RMKS補助抽出。100件ずつページ表示。地域・プリフィックスは条件判定に必要なら手動指定。
4. 保存済みルールを選択して全対象を採点。100件ずつ全件の得点・マルチ・採用条件を表示。未確定だけの絞り込みも可能。管理画面と選択ルール編集に接続。

5. 形式別の提出情報、交信情報の補完、出力テキストの確認とファイル保存。JARL R1.0/R2.1、Cabrillo 2.0/3.0、zLog令和版CSVに対応します。詳細はCONTEST_OUTPUT.md。

戻る操作は入力を保持します。対象条件を変更して再読込する場合は、ナンバー作業を初期化する前に確認します。原本の外部変更を検知したら集計を停止し、対象画面で再読込します。作業ナンバーは今回の画面内だけに保持し、閉じる際に確認します。元ログは一切変更しません。

## ナンバー抽出と確認

絞り込み文字列と既知のQSL方法を除いたRMKSから、独立した数字・前後英字の候補を取り出します。001A / H101 / PM95 / 08HWなどの文字と先頭ゼロを保持します。コールのスラッシュ、日付、周波数の一部分を切り出しません。自由記述の意味を自動で保証する処理ではありません。

単一候補は「候補・要確認」で空欄へ入力し、ページ単位の確認または手入力で確定します。複数候補は状態欄へ表示し、受信番号を自動入力しません。既存の手入力を上書きしません。未確認候補が残る場合、総得点は未確定です。RSTは元QSOと別に保持します。

## ルール管理

新規作成、検索、編集、複製、保存、別名保存に対応。保存先はconfig/rules/{識別子}_{参照年}.txt、内容はUTF-8のJSONです。名称・参照年・出典URLを記録します。参照年変更は「別名保存」で過去年版を残します。同名の別名保存・新規保存は拒否し、既存を勝手に置換しません。

既存の保存は読込時のスナップショットで外部変更を検出し、config/rules/history/に変更前を保存してから一時ファイル経由で置き換えます。historyは履歴の参照用で、現在は専用の復元画面を持ちません。全体ZIPバックアップのconfigにも含まれます。

画面には基本・通常点、条件別得点、第一・第二マルチ、JSON直接編集のタブがあります。条件編集画面はAND/ORグループと単独条件を作成できます。JSONを変更した場合は明示的に検証・画面反映してから保存します。未知キー、未対応演算、重複JSONキー、非有限数等は拒否し、黙って情報を削除しません。得点・係数は0～100000000、小数6桁までです。

## 採点処理の定義

- 電話（SSB/USB/LSB/FM/AM）、電信（CW）、既知デジタルは別の通常点。FT8/FT4/FT2/FreeDVの補足表記も分類します。未定義モードはエラーで総得点を未確定にします。
- 対象は日時順。重複判定は相手コール・バンド、必要ならMODE文字列を含めます。先行する正常判定交信との重複は0点、条件点より優先です。
- 条件点は上から最初に一致したものを採用。文字条件（等しい・異なる・先頭・カンマ区切り候補）と文字数・単一数字群桁数（等しい・異なる・以上・以下）、AND/ORを扱います。空のANDは全件、空のORは該当なしです。
- 地域とプリフィックスは専用作業欄の値です。コールからのDB自動判定は未接続。条件に必要な情報がない場合は未確定です。「4桁以上」を勝手に「県内」に読み替えません。
- 第一マルチ：未使用、ナンバー全体、単一数字群、開始位置（0起点）＋文字数。バンド別または全体のユニーク数。数字群が複数なら連結せずエラー。スライスの範囲不足もエラー。
- マルチに数える有効交信は、重複でなく得点が0より大きい交信とします。異なる定義を必要とする大会はエンジンの拡張が必要です。
- 第二マルチ（FD係数など）：未使用、固定値、条件一致の有効交信バンド数、条件一致の有効交信数。固定0・集計0は正当で、1に補正しません。
- 集計は「総交信得点×M1×M2」または「バンドごとの得点×M1の合計×M2」。後者は第一マルチのバンド別設定を必須とします。未使用のマルチは乗算なし相当（内部1）です。
- エラー時の表示得点・マルチは判定できた部分の参考値であり、確定総得点は出しません。候補未確認も同様です。

ルール変更後は再集計します。現在はQtタイマーで計算開始をまとめており、計算自体はUIスレッドで行います。非常に大きなログでは計算中の操作が一時停止する可能性があります。

## 1.00の残作業と1.01

段階5の各形式の提出情報と出力、Cabrilloテンプレート管理を追加しました。登録ルールによる複雑なマルチ抽出、地域・大陸・プリフィックスDB照合、交信ナンバー作業の永続保存などは本チェックポイントでは未実装です。JARLのタグ構造はユーザー提供の提出例と公式仕様、CabrilloはWWROFとCQ WWの仕様、zLogは現行公式ソースを照合しました。実機・提出受付での確認は別途必要です。

コンテスト機能・ルール管理・テンプレート管理そのものは1.00の範囲。大会別のルールを検証してまとめた配布パックと細かな改修は1.01の予定です。本版に公式大会の検証済みプリセットは同梱していません。新規画面の通常点1は編集開始値であり、大会規約の値ではありません。

採点処理はDecimalによる十進数演算を使い、小数点数の二進浮動小数点誤差による整数得点の誤判定を避けます。Cabrillo総得点・zLog交信得点に非整数値が残る場合は丸めずエラーにします。

## 国・地域／大陸の参照（最新追補）
段階3に参照ボタンと国・地域名、大陸の作業欄を追加。CTYの版を示して100件ずつ
候補を表示し、利用者がチェックした交信だけ空欄へ反映します。既存の国名または大陸が
候補と異なる場合は、その交信の両項目を保持し反映しません。国内地域と大会用プリフィックスは変更しません。
国名・大陸は手入力も可能。候補不明の移動局は手動確認します。原本TXTは不変。
ルール条件にcountry（国・地域名）とcontinent（AF/AN/AS/EU/NA/OC/SA）を追加。
必要な値がない場合は未確定、不正な大陸コードもエラー。通常点と第二マルチの条件で使用できます。
国名条件は作業欄の文字列比較であり、表記揺れやDXCC番号を自動統合しません。
CTYの代表プリフィックスを大会マルチへ自動転用しません。
採点への入力は確認して反映した作業値。参照DB変更で既存作業値が自動変更されることはありません。
既存のルールはそのまま読めます。新条件を使ったルールは古いアプリでは非対応として拒否されます。
作業欄の再起動後の永続保存、国内県内外の自動判定、大会固有の派生規則は引き続き残作業です。

## 最新追補: 採点進捗
1,000件を超える対象では採点を100件単位のQtタイマー処理に分け、進捗表示と操作受付を行います。ルール変更・戻る・閉じる時は旧計算を破棄。完了時に原本とルールのスナップショットを再確認します。採点中は提出情報へ進めません。1,000件以下は従来の同期計算です。最終表示用データ構築、ファイル読込・出力生成は同期処理で、あらゆる操作が無停止になったという意味ではありません。重い複雑条件の1交信計算を時間制限で中断する方式でもありません。
