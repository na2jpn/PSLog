# QSL受領一括処理 — PSLog 1.00 開発チェックポイント

編集メニューの「QSL受領一括処理」から使用する。1回のTXTには1種類の受領方法を適用する。自動でカード発送や外部サービスへの送信は行わない。

## 入力・照合

- 1行に日付、時刻、相手コールの3項目。JCC/JCGが分かる場合はコードを1項目追加した4項目も受け付ける。空白区切りで、3項目/4項目とも順序自由。全角をNFKC正規化する。
- 任意JCC/JCGは4桁JCC、5桁JCG、5桁+補助英字、6桁JCCの正規コードを受け付ける。海外局などコード不明時は従来どおり3項目でよい。入力コードは照合時の確認情報として保持・表示し、QSL受領処理ではログのJCC/JCG欄を変更しない。
- 日付は4桁年、ハイフンまたはスラッシュ区切り。月日と時はゼロ埋め不要。時刻は `5:10` / `05:10` のようにコロン必須で分は2桁。秒や `0510` のようなコロンなし時刻は受け付けない。
- UTF-8 BOMあり／なし、または明示指定のCP932。文字コードやJST／UTCを推測しない。
- UTCは9時間加算してJSTへ。日付・年をまたぐ照合を行う。
- 対象基本コールに完全一致する自局、および基本コール直後に `/` がある自局を対象とする。ファイル名の `-1` は `/1` として扱う。似た別コールの前方一致は含めない。
- 相手コールは大文字小文字を無視した完全一致。相手の移動サフィックスを勝手に省かない。
- 時刻差は正負どちらも10分未満。10分ちょうどは含めない。
- 候補1件は選択済み。複数候補は保留から手動選択する。時刻が最も近い候補を自動採用しない。自局、日時、BAND、MODE、MY QTH、ファイル名・原本行を示す。
- 全入力行をCSVへ出す。空行、不正行、未一致、未確定は原本を更新しない。同一交信を複数行で選んでも1回だけ更新する。
- 対象ログに読み取り問題があれば照合を停止して修正を案内する。照合後の入力変更・対象ログの変更・追加・削除は反映直前に検出し、再照合を要求する。

## 受領方法とRMKS

BURO.R / CARD.R / 1way.R / Direct.R / LoTW.R / eQSL.R / hQSL.R / QRZ.R / Other.R。

独立した既知トークンだけを大文字小文字を無視して認識する。空白、括弧、カンマ、セミコロン等で区切られたものは認識する。英数・日本語等の単語文字、ドット、スラッシュ、ハイフンに隣接するものは認識しない。例えば `BURO.Rなし`、`https://BURO.R` は受領済みと見なさない。文末の `BURO.R.` も確認対象として残る。未知の `.R` は初回判定を解除しない。この保守的な境界規則はメインのQSL表示にも共通化した。

対応する待ち状態は受領状態に置換する。CARDは保持し、CARD.Rを補助追記する。同じ受領トークンが既にあれば再追記しない。他のメモやトークンには手を加えない。ログのRMKS部分だけを書き換え、古いRST、他の項目、BOM有無、改行、10項目の旧形式も維持する。

## 二つの確認対象

「初回QSL確認」は更新前RMKSに既知の受領トークンが一つもない交信。局や地域単位で新しいアワード対象かどうかは断定しない。

「BURO発送記録なし」は今回BURO.Rを付ける際、更新前にBUROもBURO.Rもなかった交信。他方式でQSL済みでも立てる。発送忘れを断定せず、人が返送要否を確認する。

| 更新前 | 今回 | 初回QSL | BURO発送記録なし |
| --- | --- | --- | --- |
| BURO | BURO.R | あり | なし |
| BURO hQSL.R | BURO.R | なし | なし |
| hQSL.R | BURO.R | なし | あり |
| メモのみ | BURO.R | あり | あり |
| BURO.R | BURO.R | なし | なし・変更なし |
| CARD | CARD.R | あり | なし・CARD保持 |

両フラグは更新前に判定しCSVへ残す。利用者の承認どおり、確認対象でもCSVを保存できれば受領状態まで反映する。

## 結果と原本の保護

既定の結果保存先は `reports/`。実行ごとに日時＋UUIDの専用フォルダーを作り、`result.csv` と `journal.json` を保存する。同名の既存結果は上書きしない。CSVはUTF-8 BOM付き、CRLF。

CSVは入力行番号・原文、入力時刻基準、変換後JST、照合状態、候補全件のJSON、選択候補、時刻差、二つの確認フラグと理由、実自局、相手コール、JST/UTC日時、BAND、MODE、RST送受、HIS QTH、**その交信のMY QTH**、JCCJCG、RMKS更新前と更新予定、受領方法、原本パス・行、重複元行、実際の更新状態、バックアップ、前後SHA-256を含む。CSV列名はqsl_batch.pyのCOLUMNSで固定する。住所や出力など元ログにない情報は作らない。

1. 外部変更を検査し、更新前情報を含む結果CSVと回復記録を保存する。
2. 変更する全原本を先にバックアップする。
3. ファイルごとに「処理中・成否要確認」を結果へ保存してから、一時ファイルを検証し原本へ安全置換する。
4. 実際に保存できたものだけ「保存済み」と記録する。全完了後は「完了」。

CSVを最初に保存できなければ原本は変更しない。途中でCSV更新や原本保存が失敗した場合は、それ以降の原本更新を止める。保存済み／未保存／未処理を可能な範囲で記録する。原本保存後に結果ファイルが書けなくなった場合や異常終了では「処理中・成否要確認」が残ることがある。処理ID、バックアップ、前後ハッシュを含むjournal.jsonと原本を照合する必要がある。原本と結果ファイルをまとめた原子的なトランザクションではない。自動回復・自動ロールバックの画面は未実装。再照合して処理し直す際も、**最初の結果を捨てないこと**。更新前の初回・BURO発送確認フラグは最初のCSVに残る。
