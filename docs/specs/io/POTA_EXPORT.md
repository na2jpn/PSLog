# POTA提出用ADIF — PSLog 1.00 開発チェックポイント

「入出力 → 特殊なエクスポート → POTA提出用ADIFファイル」から開く。特殊なエクスポート配下には今後の追加先としてSOTA提出用CSVも並べ、現段階では無効にする。コンテストメニューは既定の3項目のまま。

## 操作

自局コールの検索文字で候補を絞り、出力元の自局を選択する。その自局に完全一致するログだけをチェック付き一覧に表示する。対象ファイルを選び、任意でJSTの日時範囲（YYYYMMDDhhiiss、両端を含む）とRMKSの部分一致を指定する。RMKSは英字の大文字小文字を区別せず、期間条件とのAND。

運用コールサインは出力元自局を初期表示し、出力時に変更可能。OPERATORは別途指定する。元TXTは変更しない。複数OPの期間が混在する場合は、対象を分けて出力する。

自局の公園番号は1件または複数。空白・カンマ・セミコロンで区切る。全角を半角に、大文字へ正規化する。重複番号はエラー。字句形式は英字1～4文字、ハイフン、数字4桁以上。公園の実在・現在の番号・同時運用可能性は判定しない。指定した全公園へ、抽出した全交信をそれぞれ出力する。別日の別公園運用を混ぜずに対象を指定する。

画面は左右配置。出力内容プレビューや必須の確認段階は設けず、「POTA用ADIFを出力」で検査して保存する。ファイル一覧はスクロールし、小さい画面では共通のウィンドウ補正・スクロール機構を使う。

## 出力仕様

POTA公式の [Logging Made Easy](https://docs.pota.app/docs/activator_reference/logging_made_easy.html)（ページ更新日2026-07-08、参照2026-09-11）を確認した。公園タグ、運用者と運用コールの区別、複数公園での公園別ファイルを参考にした。

| 項目 | 出力 |
| --- | --- |
| CALL | 相手コール |
| QSO_DATE / TIME_ON | PSログJSTから9時間戻したUTC。分精度のため秒は00 |
| BAND | 既存ADIFバンド対応表 |
| MODE / SUBMODE | 既存ADIFモード対応表。FT4はMFSK/FT4、FreeDVはDIGITALVOICE/FREEDV等 |
| STATION_CALLSIGN | 画面の運用コールサイン |
| OPERATOR | 画面で指定した運用者 |
| MY_SIG / MY_SIG_INFO | POTA / 指定した自局公園番号 |
| MY_STATE | 任意入力があるときのみ |
| RST_SENT / RST_RCVD | 原本の送受レポート |

POTA向けのASCII ADI、CRLF、BOMなし。日本語RMKSは絞り込みには使うが、提出用ファイルにはRMKS・QTH・アプリ独自の補助項目を含めない。元ログにはそのまま残る。未知のMODE/BANDは推測変換せず、該当ファイル名・行を表示して停止する。FT8 AS等の補足付き表記は基本モードで出力し、完了欄で通知する。

自局公園×UTC日でファイルを分ける。2fer等では公園ごとに同じUTC日時を使う。提供されたj2jtx2p.zipのPHPはADIF入力の変換ツールであり、MY_SIG/MY_SIG_INFO、OPERATOR等の参考にした。同PHPの1分時刻調整は採用しない。

ファイル名は `JH1HST-1@JA-1222-20260911.adi` の形。コール中のスラッシュはハイフンに置換。同名があれば `_001` から連番を付け、既存ファイルを上書きしない。日付はUTCの日付。交信日時の古い順に出力し、原本の重複行を勝手に削除しない。

複数地域にまたがる公園用にMY_STATEを任意指定できる。空欄の場合はPOTA提出時の地域指定を利用する。所在地名からの地域コード推定は行わない。相手公園のSIG/SIG_INFO（P2P）を手書きRMKSから推測する処理は未実装。

## 保存保護と制約

すべての出力データを検査・構築してから保存を開始する。選択した元TXTのスナップショットを各保存前に再確認する。変更を検出したら停止する。出力ファイルは一時ファイル検証後に新規作成し、既存ファイルと競合したら次の連番を使う。

複数ファイル出力は一括原子処理ではない。途中で失敗した場合、作成済みパスを例外情報に保持し、画面へ件数とファイル名を表示する。元TXTはどの経路でも変更しない。実際のPOTAアップローダーへの提出は未検証で、自動提出機能もない。
