# 年をまたぐ交信編集 — 1.00開発版

編集画面でDATEの年を変更すると、移動先の絶対パスを表示して確認します。
「いいえ」が初期選択です。自局の運用サフィックスとログ付与文字を保ち、年だけ異なる
ファイルへ編集後の1交信を追加し、元ファイルの対象行を除去します。
既存の移動先に同じ交信があっても、編集対象を黙って統合・消去しません。

両方の既存ログを事前バックアップします。対象以外の行、既存BOM・改行を保持。
新しい移動先はUTF-8 BOM付き・CRLFです。移動元が空になってもファイルは残します。
解釈不能行がある移動元/先、読込後の外部変更では保存を停止します。

## 中断からの回復

bak/year_moves/に変更前後の全バイトを含むpending.jsonを先に保存し、
移動先への追加、移動元からの削除の順で反映します。両方の完了後にdone.jsonへ改名します。
これは保存意図の回復記録で、プロセスの存在を示すロックファイルではありません。
排他は従来どおりOSが解放するロックです。

途中エラーが出たら、同じ編集を繰り返さずメインの「ログを再読込」を使用してください。
再起動後の自局ログ読込でも回復します。またlogbookの保存用ロック取得時に未完了を確認し、
別の書き込みより先に保存済みの変更を完了させます。両ログの現在内容が記録した変更前または
変更後に一致する場合だけ続行します。既に変更後なら追加を繰り返しません。

外部編集でどちらにも一致しない場合、両方を事前照合して回復を停止します。
画面に出る回復記録、現行両ログ、バックアップを保全して比較・確認してください。
pending記録を単に削除して解除すると、重複・取り残しを見逃すため、削除で解決しないでください。
競合を対話的に解決する専用画面はこの版に含みません。

回復記録は自動世代削除せず残します。原本と同じ交信情報を含みます。
全体ZIPバックアップは従来のconfig/logbookのみで、この回復履歴は含みません。
未完了処理は全体バックアップの保存用ロック取得時にも先に回復し、競合時は作成を停止します。

## 検証と限界

155件の開発テスト成功（Linux Qt offscreen）。追加8件は、保存前・片方保存後・両方保存後の
中断回復、再回復しても二重追加しないこと、外部変更時の回復と後続書き込み停止、
既存移動先のBOM/改行保持、バックアップ失敗、壊れた記録、編集画面の確認/取消です。
以前の「別年編集を拒否」テストは、移動と元年バックアップを検証するテストへ変更しました。

この回復方式は年変更編集用です。インポート/QSL一括更新の回復は未接続。
複数ファイルの同時原子置換ではなく、保存意図を使った完了方向の回復です。
一般の外部エディターはPSLogのロックに従わないため、最終照合直後の競合は完全には防げません。
Linuxでは原本と記録のディレクトリfsyncも行いますが、ストレージ機器の物理電源断、
Windowsの永続化・排他、Windows EXEでの実動作は未検証です。
