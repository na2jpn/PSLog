# PSLog Ver1.02 メイン画面・セッションタブ仕様

状態: **Ver1.02 実装済み・Windows実機確認済み・確定**  
作成: 2026-09-16

この文書は、Ver1.02のメイン画面タブ化とコンテスト高速入力モードについて、合意した仕様と実装内容をまとめたもの。
Ver1.02確定までにWindows/PySide6実機で表示・操作確認と修正を行い、2026-09-17にVer1.02最終仕様として確定した。

## 1. 基本方針

- PSLog TXTの内部データ形式（11固定項目）は変更しない。
- 「標準」「コンテスト」で変えるのは主に表示、配置、入力導線、ラベル名、セッションごとの保持状態。
- 内部項目名は従来のままとし、画面上だけ別名表示してよい。
  - 例: コンテストモードでは `RMKS` を **コンテストナンバー** と表示する。
- 従来の「画面モード → 標準 / コンテスト」という単一切替案は、**メイン画面全体をセッションタブ化する案で置き換える**。

## 2. メイン画面のタブ化

メイン画面上部にセッションタブを置く。

例:

```text
[標準] [標準2] [AADX] [JA0] [KANAGAWA]   ＋
```

### 2.1 セッション種別

- 標準セッション
  - 現在のメイン画面と同等のレイアウト・操作。
  - 最大 **5** セッション。
  - 標準1〜5はすべて同じ標準デザインを使う。
- コンテストセッション
  - コンテスト高速入力専用レイアウト。
  - 最大 **6** セッション。
- 合計最大 **11** セッション。

上限に達していても `＋` メニュー項目は選択可能とし、選択後に「標準タブの上限に達しています」「コンテストタブの上限に達しています」と理由をダイアログ表示する。最近閉じたタブの再開時も同様とする。

### 2.2 `＋` の役割

タブ列右端に `＋` を置く。`＋` はページではなく追加/再開操作の入口とする。

候補:

- 標準タブを追加
- コンテストタブを追加
- 最近閉じたタブを再開
- 既存のセッション/ログを開く

「最近閉じた」の履歴は、誤ってタブを閉じた場合の復帰手段として使う。履歴は最新20件を保持する。`＋` はSET等と同じプライマリボタン系の外観にし、追加操作であることが分かるようにする。

### 2.3 タブを閉じる操作

- タブが2個以上あるときは各タブに `×` を表示する。
- 中クリックでも閉じられるようにしてよい。
- 右クリックメニューにも「このタブを閉じる」を置いてよい。
- **タブを閉じてもログファイルは削除しない。**
- タブが1個だけになったら:
  - `×` を非表示。
  - 中クリック閉じを無効。
  - 通常操作で0タブにできないようにする。

### 2.4 0タブ異常時の自己修復

設定破損、復元失敗、予期しない状態などで有効なセッションが0件になった場合、起動時に自動で **標準セッションを1個作る**。

不変条件:

> PSLogのメイン画面には、起動完了時に最低1つの有効なセッションが存在する。

## 3. 起動・終了・セッション復元

### 3.1 初回起動のコールサイン入力

現行の初回起動時コールサイン入力は残す。

起動順序の考え方:

1. 保存済みセッションがあれば復元する。
2. 復元結果が0件なら標準セッションを1個作る。
3. その標準セッションに使える保存済みコールサインも無ければ、従来どおり初回コールサイン入力を出す。

したがって、初回コールサイン入力とセッション復元は競合させない。

### 3.2 PSLog再起動時の復元

PSLogを正常終了した場合も、クラッシュ等で再起動した場合も、可能な範囲で前回開いていたセッションを復元する。

少なくとも保存対象とするもの:

- セッション種別（standard / contest）
- タブ順
- 前回選択していたタブ
- 対応ログファイル
- 自局コールサイン
- コンテスト英名（コンテストのみ）
- Band（コンテストのみ）
- Mode（コンテストのみ）
- MyQTH（コンテストのみ）

入力途中の相手コールサイン / コンテストナンバーまで保存するかは未確定。

### 3.3 色はセッション保存しない

コンテスト識別色そのものはセッションデータへ保存しない。
起動・表示時に、現在開いているコンテストタブの左から順に固定パレットを割り当てる。

## 4. レイアウトとスクロール

### 4.1 タブバー位置

タブバーはメイン内容のスクロール領域の外に置き、常に見えるようにする。

```text
メニューバー
既存の上部ライン等
セッションタブバー  ← 固定
--------------------------------
現在のセッション画面
```

タブ追加によってウィンドウ全体に余分な縦スクロールが発生しないようにする。

### 4.2 現在の黄色いステータス欄

現在メイン画面下部にある、例:

```text
0交信を読み込みました。要確認行 0件。
```

のステータス表示は、**LogSearch枠の下部へ移動**する。

これにより、タブバー1段分の高さを確保し、LogSearchのリスト部分が少し短くなることは許容する。
画面全体にスクロールが増えるより、LogSearch内部の表示行数が少し減る方を優先する。

## 5. 標準セッション

- 現在の標準メイン画面の見た目・操作を基本的に維持する。
- 標準1〜5はすべて同じ落ち着いた標準色を使う。
- 標準セッションにはコンテスト識別色を使わない。
- 標準画面のGroupBox等の罫線も現在の標準デザインのままとする。

追加標準セッションのログ命名・初期コールサイン継承の細部は実装時に最終確認する。

## 6. コンテストセッションの目的

コンテスト中は、Band / Mode / RST / 自局情報などを事前に固定し、QSOごとの入力を極力:

```text
相手コールサイン → コンテストナンバー → 記録 → 次
```

まで短くする。

1交信10秒未満の運用も想定し、標準ログ画面の全項目を毎回触らせない。

## 7. コンテストセッション作成

### 7.1 コンテスト英名

標準画面の「自局コールサイン」横にある付与文字相当の位置/役割は、コンテストセッションでは **コンテスト英名** とする。

- 入力許可: アルファベットと数字のみ。
- 表示・ファイル名では大文字化してよい。
- 例: `aadx` → `AADX`
- コンテスト英名はタブ名にも使う。

### 7.2 コンテストログファイル名

同名コンテストの年内複数開催も考慮し、年月を含める。

基本案:

```text
YYYY_CALL_CONTESTYYYYMM.txt
```

例:

```text
2026_JH1HST_AADX202609.txt
```

同じ自局コールサイン・英名・年月を指定した場合は、現時点では同じログファイルを再利用する。
同一英名・同一年月で意図的に別ファイルが必要な特殊ケースの枝番規則は、必要になった時点で追加検討する。

## 8. コンテスト画面レイアウト

コンテストセッションには少なくとも2つの主要GroupBoxを置く。

### 8.1 共通設定

- Band
- Mode
- MyQTH

挙動:

- BandはQSO記録後も維持。
- ModeはQSO記録後も維持。
- MyQTHはセッション中維持。
- MyQTHは自局コールサインのPrefix等から初期補助してよい。
- ユーザーが変更したMyQTHは以後そのセッションで保持する。
- `Japan` のような国名のみでも許容する。

### 8.2 交信入力

表示する主要項目:

- 相手コールサイン
- コンテストナンバー
- Date / Time
- RST

内部マッピング:

- コンテストナンバー → `RMKS`
- Date / Time → 従来の `DATE` / `TIME`
- RST → 従来の `RTSs` / `RTSr`

画面上では `RMKS` という名称を見せず、**コンテストナンバー** と表示する。

高速操作の基本導線:

1. 相手コールサイン入力
2. コンテストナンバー入力
3. Enter等で記録
4. 次のQSO用に相手コールサインへフォーカスを戻す

TAB順もこの高速入力を優先する。


### 8.3 バンド別QSO数

コンテスト画面の左側で、交信入力欄を必要以上に縦へ引き伸ばさない。余った領域には **バンド別QSO数** を簡潔に表示する。

- 集計対象は **現在選択中のコンテストタブ/ログだけ**。
- 別コンテストや標準ログは混ぜない。
- 交信のあるバンドと、現在選択中のBandを表示する。
- 現在Bandがまだ0件でも `7 MHz 0` のように表示する。
- 表示例: `7 MHz 18　14 MHz 7　21 MHz 3　｜　合計 28`
- QSO記録、ログ再読込、Band変更時に更新する。
- このGroupBoxの罫線も、選択中コンテストの識別色に合わせる。

## 9. RSTの扱い

- Modeに応じて既存PSLogのRST初期値を使う。
  - 例: CW/RTTY系は599、Phone系は59。
- コンテストセッションではBand/Modeと同様、RSTの自動維持を基本とする。
- 標準画面にある「維持」のような操作をコンテスト中に誤って解除できない設計を想定する。

例外的にRSTを手動変更した値はその1交信には使用できる。記録完了後は、次QSOでの引きずり事故を防ぐため、現在のModeに対応する標準RSTへ自動で戻す。

## 10. His QTH / JCCJCG / 所在地補助

コンテスト画面では **His QTH入力欄を表示しない**。
所在地補助の通常UIも表示しない。

ログ記録時には、相手コールサインPrefixから分かる **国名だけ** をHis QTHへ補助する。

例:

- JA系 → Japan
- K系 → United States
- DL系 → Germany

日本局でもJCC/JCGや市区町村をコンテスト入力画面で推測・要求しない。
内部11項目形式は維持する。

## 11. コンテスト用LogSearch

コンテストセッションではLogSearchをそのセッション/ログ向けに簡略化する。

- 「選択のログに限定」はデフォルトでON。
- 標準LogSearchにある以下の表示列はコンテストでは外す:
  - QTH
  - JCCJCG
  - QSL
- 代わりに **コンテストナンバー**（内部RMKS）を表示する。

想定例:

```text
Date | Time | Band | Mode | Callsign | RSTs | RSTr | Contest No.
```

厳密な列順・列幅は実装時に画面を見ながら調整する。

## 12. コンテスト識別色

### 12.1 標準タブ

標準1〜5はすべて現在の標準デザインを維持する。
緑系はPSLog標準側で使われているため、コンテスト識別色には使わない。

### 12.2 コンテスト色パレット

コンテストタブは左から順に次の6色を固定順で割り当てる。

1. 青
2. 朱
3. 紫
4. 茶
5. ターコイズ
6. ピンク

現在開いているコンテストタブ同士で同じ色が出ないことを保証する。
閉じたタブの色は、次に表示される順序に応じて再利用してよい。

### 12.3 色を付ける場所

コンテストタブ:

- 背景: その色のかなり薄い色で全面を塗る。
- 文字: 濃い同系色。
- 外枠: 濃い同系色で明確にする。

選択中コンテスト画面:

- 「共通設定」GroupBoxの罫線
- 「交信入力」GroupBoxの罫線
- `LogSearch` GroupBoxの罫線

をタブと同じ濃い識別色にする。

本文画面全体を派手な色で塗ることはしない。
目的は、複数コンテスト同時運用時に **現在どのコンテストへ記録しているかを瞬時に判別すること**。

## 13. 複数コンテスト同時運用

PSLogのプロセスを複数起動するのではなく、1つのPSLog内で複数コンテストセッションを同時に開くことを基本案とする。

例:

```text
[標準] [AADX] [JA0] [KANAGAWA]  ＋
```

各コンテストセッションは少なくとも以下を独立保持する。

- 対応ログファイル
- コンテスト英名
- Band
- Mode
- MyQTH
- 入力中の状態（保存範囲は一部未確定）

将来、ショートカット（Ctrl+1等）でタブ切替を高速化する余地を残す。

## 14. 実装時に壊してはいけないもの

- PSLog TXT 11固定項目。
- 標準モードの既存保存・入力・検索・編集処理。
- 初回コールサイン入力。
- 既存のバックアップ/復元方針。
- タブを閉じる操作によるログ削除は禁止。
- セッション復元失敗で空画面にしない。

## 15. 実装時に確定した事項 / 今後の余地

- コンテストRSTを手動変更した場合、その1交信だけに使用し、保存後はMode標準RSTへ戻す。
- コンテスト高速入力では、標準画面の `confirm_record` 設定にかかわらずQSOごとの確認ダイアログを出さない。
- 入力途中のCall / Contest No.はセッション永続化対象にしない。開いているタブ、ログ、自局、Band、Mode、MyQTH等を復元対象とする。
- 追加標準セッションは現在の自局コールサイン・Band・Mode・MyQTHを初期値として継承し、ログ付与文字は空欄から開始する。
- `＋` メニューには標準タブ追加、コンテストタブ追加、最近閉じたタブの再開を実装した。閉じたタブのログは削除しない。最近閉じた履歴は最新20件。
- コンテスト追加時には自局コールサイン、コンテスト英名、対象年月 `YYYYMM` を入力する。
- 同一コール・同一英名・同一年月は同じログへ戻る。別ファイルを必要とする枝番規則は未実装。
- 「既存ログから開く」専用選択UI、タブ右クリックメニュー、Ctrl+数字等のタブ切替ショートカットは将来拡張余地として残す。

## 16. Ver1.02最終実装で追加確定した安全・操作事項

- WindowsではPSLog本体を名前付きMutexで二重起動禁止とする。複数標準ログ/複数コンテストはタブで扱う。
- `＋` はSET等と同じプライマリ系ボタン表示とし、追加操作であることを分かりやすくする。
- 標準5 / コンテスト6の上限到達時も追加メニューは選択でき、選択後に上限理由をダイアログ表示する。最近閉じたタブの再開時も同じ。
- タブ名と `×` の間隔はスタイル側で確保し、`tabText()` の文字列へ空白文字を付加しない。
- 小画面ではメイン内容を潰し切らず、必要時に縦スクロールが発生する最低コンテンツ高さを維持する。
- 相手コールサインのサンプル/placeholderは `JX1XXX` を使用する。
- コンテスト画面では選択中ログだけのバンド別QSO数を表示する。
- 最近閉じたタブ履歴は最新20件。
