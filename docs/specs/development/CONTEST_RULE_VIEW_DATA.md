# コンテストルール表示データ

Ver1.069 PATCH09 FIX1 で、コンテストの**表示専用**規約情報を `event.rule_view` に分離した。

目的は、採点・提出用の確認事項 (`required_flags` 等) から「呼び出し方法」「周波数制限」などを推測して表示しないこと。規約表示は公式資料で確認できた事実だけを登録する。

## 原則

- `rule_view` は表示専用。採点、提出可否、確認チェックボックスを制限しない。
- 公式規約または保存済み一次資料に明記された内容のみ登録する。
- 未登録項目は無理に推測せず「規約表示データに未登録（公式規約を確認）」と表示する。
- `required_flags` は提出・採点上、本当にユーザー確認が必要な条件だけに使う。
- 「インターネット禁止」「ソフトウェア禁止」等の解釈が広がる事項を確認チェックへ安易に入れない、という既存方針を維持する。

## 対応フィールド

- `participants`
- `power`
- `movement`
- `call_method`
- `counterparts`
- `frequency`
- `restrictions`
- `exchange`
- `repeat`

表示画面では「周波数制限」独立行を出さず、上部の「対象バンド」を参照する。
`restrictions` は「特殊なルール」と表示し、明示された大会固有の禁止・制限と時間条件を同じ欄にまとめる。
`submission_notes` は表示専用の任意項目で、提出方法・送付先・締切上の注意を「提出」欄に表示する。
内部向けの `submission.instructions` はそのまま画面へ表示しない。「その他」は参照年とルールIDのみ。

## 監査

`python devtools/audit_rule_view.py`

で、登録済みルールの表示専用データの不足項目を一覧できる。

2026-09-22時点では愛・地球博記念コンテストを最初の完全登録例とし、他大会は公式資料を確認しながら順次登録する。推測で一括補完しない。

## 2026-09-23 先行15大会の表示方針

- `points_display` と `multipliers_display` は公式規約に基づく得点・マルチの表示専用文章。採点計算には使用しない。
- `submission_deadline` は提出期限の表示専用文章。提出可否の判定には使用しない。
- 大会全体または電話部門全体など大枠の出力制限がない場合、共通「送信出力」欄は「制限なし」。QRPなど個別種目の出力条件を共通欄へ混ぜない。
- 大会固有の移動条件が `movement` に登録されていない場合、「移動運用」行は非表示。移動局の提出時OPPLACE必須判定は従来どおり別管理。
- JA8は機械的な基本点数表示に加え、「特殊なルール」に年代別符号による実得点を示す。年代別符号はマルチには含まない。
- SWLは公式の参加資格を表示する。未実装のSWL部門を追加したと誤認させない。
- `devtools/contest_rule_view_verified_15.json` が先行15大会の表示専用生成元。既存の各大会ビルダーは保存前にこのデータを適用する。
- QSOパーティは専用画面で扱い、コンテスト一覧・コンテストルール一覧には表示しない。
