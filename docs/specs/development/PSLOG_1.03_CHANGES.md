# PSLog Ver1.03 — Final Change Specification

基準: `PSLog_1.02_CANONICAL_SOURCE.zip`  
確定正本: `PSLog_1.03_CANONICAL_SOURCE.zip`

## 1. コンテスト提出

### 1.1 交信ナンバー確認

- 10件単位ページングは表示上の都合だけ。
- `全件を確認済みにする` で対象全件の「候補・要確認」を一括確認。
- `候補なし` / `複数候補` / `規約外候補` は自動承認しない。
- `受信ナンバー候補をRMKSから再抽出` は規約/候補解析を使用。
- `RMKSを受信ナンバーとして全て入れる` は対象全QSOのRMKS全文を直接コピーする自己責任機能。元ログは変更しない。

### 1.2 提出情報

- `提出コールサイン` を編集可能。移動運用の `/0` 等を許容。
- 部門名称は選択済み部門から自動入力し、任意項目として編集/空欄可。
- 登録クラブ番号/名称は保存対象で次回も復元。
- クラブ対抗の対象地域/局種に該当しないことだけを理由にPSLog側で提出を止めない。
- 入力済みクラブ情報は出力し、採用/無視は提出先判断に委ねる。

### 1.3 JARL R1.0 / R2.1 必須項目

JARL公式サマリー作成画面の必須表示を基準にする。

- 共通必須を提出前に検証。
- R1.0: 従事者資格、出力の記載区分（定格/実測）を必須。
- R2.1: R1.0専用項目は要求しない。
- R2.1フィールドデー等の条件付き必須は該当時だけ検証。
- 必須エラーは赤字太字で具体的に表示。
- 保存には `入力内容を確認` が必要。確認後に入力変更した場合は再確認を要求。

### 1.4 提出TXT再読込

- コンテスト/部門選択後、以前PSLogが作成したJARL R1.0/R2.1 TXTを読み込める。
- 現在の原本ログへQSOを照合し、原本は変更しない。
- 交信ナンバー、提出情報、確認状態、宣誓等を復元。
- 現在のルールで再採点し、総得点が以前と異なる場合は採点確認画面で停止。

### 1.5 最終画面/保存

- 総得点を赤字太字で強調。
- 保存成功時は画面内表示を維持しつつ確認ダイアログも表示。
- 標準保存先は `output/contest/`。

## 2. ログ検索・編集

- 開始/終了日時は12桁完全入力に加え先頭部分だけ入力可能。
- 未入力後続桁は検索内部のみ0扱いし、表示文字列は変更しない。
- HIS QTH / MY QTH を検索条件へ追加。
- 結果一覧は `DATE / TIME JST / 相手コール / BAND / MODE / RMKS / HisQTH / MyQTH / 元ログ`。
- 最大表示件数は初期1000、1以上の整数を指定可能。
- 検索一致全件数と表示件数を区別して表示。
- 一覧先頭に出力対象チェック列を追加。初期状態は表示中全件ON。
- 表示一覧の全選択/全解除を提供。

## 3. 検索結果引き渡し

### 3.1 POTA / SOTA / 通常エクスポート

- 検索画面から直接各出力画面へ遷移可能。
- 対象は **表示中かつチェック済みの行だけ**。
- 最大表示件数を超えて非表示の交信は引き渡さない。
- POTA/SOTAでは検索結果使用中を赤字太字で明示し、元ログ/期間/RMKS等の再抽出条件は非表示。
- 通常エクスポートも検索結果を全ログへ勝手に拡張しない。

### 3.2 標準保存先

- 通常: `output/export/`
- POTA: `output/pota/`
- SOTA: `output/sota/`
- Contest: `output/contest/`

## 4. QSL受領一括UI

- 説明文をQGroupBox化。
  - 受領一覧TXTの形式
  - QSL更新時の扱い
  - 照合できなかった場合
- 一覧切替は `表示フィルター` と明記。
- JST/UTC指定は `受領一覧TXTの日時基準` と明記。
- 表示フィルターは表示だけを変更し、更新対象判定を変更しない。

## 5. メインUI

- タブ高さ/上下余白を確保。
- `＋` ボタンを `＋タブ` へ変更。
- Ver1.02の標準/コンテストタブ色仕様は維持。

## 6. ログファイル統合

メニュー: `編集 → ログファイル統合`

- 編集系黄色UI。
- 統合先（残す）/統合元（削除）を選ぶ。
- `ファイルチェック` 合格前は `統合を実行` 無効。
- 選択変更/外部変更でチェック状態を破棄。
- 同一年・同一基本コール系統を要求。
- PSLog書式/文字コード/内容年を検査。
- ファイル名年と内容年が矛盾する場合は停止。
- 重複キー: `DATE + TIME + CALL + BAND + MODE`。
- 重複時は統合先優先、統合元側をスキップ。
- 実行直前に両ファイルを `bak/logbook_bak/` へバックアップ。
- 統合後はDATE/TIME順にソート。
- 正常書込検証後だけ統合元を削除。
- 対象例表示には汎用コール `JX1XXX` / `JX1XXX-1` を使う。

## 7. Windowsテスト/ビルド

- GUIテスト全成功後のPySide/Qt終了時にWindows status `0xC0000409` が発生する環境差を確認。
- `build-windows.ps1` は `tools/run_tests.py` を使用。
- unittestを子プロセスで実行し出力を取得。
- exit 0は成功。
- 既知Qt終了コードでも、末尾が完全な `Ran ... / OK`、かつFAIL/ERRORなしの場合のみ成功扱い。
- それ以外は必ず失敗としてビルド停止。
