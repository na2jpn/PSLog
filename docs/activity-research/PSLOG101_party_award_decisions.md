# PSLOG101 コンテスト追加仕様・QSOパーティー・アワード 引き継ぎ

作成日：2026-09-15（UTC）

## この文書の位置づけ

PSLOG101でコンテストの一通りの実装・検証を終えた後に、利用者と決めた追加仕様と規約調査をまとめた原案。過去のPSLOG100およびPSLOG101のソース・調査資料を置き換えず、追加の判断記録として保持する。

**この文書の作成は実装完了を意味しない。** パーティー・アワードの下記追加仕様、コンテストのチェック付き対象選択とバンド・モード絞り込みは、今後ソースへ反映・検証する。既存機能との重複は着手時に確認する。

直前のコンテスト実装チェックポイントは `PSLOG101_policy_review_source.zip` と参照資料3分割、原案まとめ、START_HERE。そこでの記録は全554テスト成功、未定義0/87。今回の追加仕様をそのテスト結果で検証済みと扱わない。

## 1. 全体方針

- PSログTXTの11項目を原本とし、抽出・補完・提出対象の選択で原本を変更しない。
- 年度・開催日時は初期値を用意するが変更可能。年度違い・期間外を理由に出力を止めず、確認表示にとどめる。
- 提出期限を強制管理しない。人の判断を残し、独自の禁止条件を増やさない。
- 年度が古い資料でも、利用者が変更なしと確認した範囲を未定義・未確認扱いに戻さない。
- 別大会・別提出を勝手にまとめない。共通処理の共有と提出データの混合を区別する。
- Windows/EXEでの実使用確認は全実装後。Linuxでの画面画像をWindows動作確認と呼ばない。
- 最終ソースだけでなく、原案・規約・利用者の判断・記録例を保存する。

## 2. コンテストの追加対象選択

### 流れ

大会選択 → 自局・日時範囲・任意の絞り込み → 交信一覧で確認・選択 → 提出情報 → 出力。

既存画面にはRMKS文字フィルターがある。今後、対象選択の順序とチェック付き一覧を整える。

### フィルター

- RMKSに含む判定文字は任意の自由入力。`AT-TEST`や`FOX`を固定条件にしない。
- 空欄ならRMKSで絞らない。RMKS未記入でも、交換内容の手入力で提出可能にする。
- バンドは複数選択チェックボックス：
  `3.5以下 / 7 / 10 / 14 / 18 / 21 / 24 / 28 / 50 / 144 / 430 / 1200以上`
- コンテストの初期チェックはWARCの10・18・24以外。全選択・全解除を用意する。
- モードは `FM/SSB/AM`、`CW`、`FT*`、`その他` の4群。初期状態は全部選択。
- FT*はFT8・FT4・FT2など。その他にRTTY・FreeDV・未知のモードを含める。
- パーティーにも共通部品を利用。ただしNYPやJAG WARCに不適切なWARC除外を初期適用しない。

### 確認一覧

チェック、日時、相手コール、バンド／モード、元RMKS、送受信交換内容などを表示。不要な行はチェックを外す。抽出失敗行も表示し、手入力・修正可能。候補が複数なら勝手に結合しない。

### 同時開催の実例

秋田と福岡は期間・バンド・モードが重なり、同じ相手と同じ分に別の交換番号で交信する。

| 日時 JST | 相手 | BAND/MODE | RMKS | 対象 |
|---|---|---|---|---|
| 2026-09-13 06:39 | JK1DVP/7 | 7/CW | 04 FOX | 福岡 |
| 2026-09-13 06:39 | JK1DVP/7 | 7/CW | NH AT-TEST | 秋田 |

この2行を提出処理で一つにまとめない。原本で別行の記録を保持し、対象大会に応じて選ぶ。既存インポート重複判定への影響は着手時に確認し、今回の提出選択の議論だけで原本の重複仕様を無断変更しない。

## 3. QSOパーティー：4種類、選択項目は6つ

| 表示名の例 | 備考 |
|---|---|
| QSO パーティ NYP（JARL）（2026） | 主催者とNYPを明示 |
| JARD HAMtte交信パーティー 春（2025） | 春・夏・冬を別項目 |
| JARD HAMtte交信パーティー 夏（2025） | 同上 |
| JARD HAMtte交信パーティー 冬（2025） | 同上 |
| JAG QSOパーティー（WARC band部門）（2026） | WARCを明示 |
| 100周年/ニューカマー＆HAMtte ウェルカムQSOパーティ（2026） | 選択名の「第2回」は不要 |

年度はコンテストと同様、名称の後ろに括弧付き。開催回情報が必要なら内部・提出情報に保持するが、ウェルカムの選択名には入れず、日時範囲で対象を指定する。提出大会名は規約に合わせる。

共通の流れは、選択 → 日時指定 → RMKS等から候補抽出 → チェック付き一覧 → 提出情報・出力。

**コンテストより緩い運用を優先。** 同一局・連続交信・日付またぎなどによる自動除外や出力停止をしない。規約上の局数集計は補助として表示し、利用者が提出対象を決める。例えばHAMtteの23:59と翌日00:01は同じ相手・バンド・モードでも有効。

### 3.1 NYP

- 交換は送受信レポート＋それぞれのオペレーターネーム。
- 名前は本名・ニックネーム・ハンドル・イニシャル可。サマリーの氏名とは別に保持する。
- 自分の名前は一括設定＋必要に応じて交信別修正。原本に送信名の記録がなくてもよい。
- 相手名はRMKSの先頭固定にしない。QSLタグと周波数表記を除いた残りを候補にする。
- `433.12`のような単位なし小数の周波数も除外する。数字を含む不明文字列全般を機械的に削除する仕様までは決めていない。
- `BURO`、`hQSL.R`、`eQSL.R`等が前後に混在しても扱う。抽出結果は修正可能。
- 日本語名・スペースを含む名前も手入力可能。
- 電子提出はJARL形式。実物ステッカー希望には郵送手続きがある。PDFの一般実装を必須にしない。
- 20局条件を表示しても、パーティー共通方針に従いソフト独自の出力停止をしない。既存NYP実装にある20局未満停止は見直し対象。
- 概要2026／規約2027の年度差は、提出形式の未完成要因にしない。既存2026定義を消さない。

記録例：`NAKA BURO` → NAKA、`KAZU hQSL.R eQSL.R` → KAZU、`BURO NAKA 14.050MHz` → NAKA。レポート599なら受信欄は `599 NAKA`。

### 3.2 JARD HAMtte パーティー部門

- 利用者確認：提示された2022年夏規約から2025年まで変更なし。別年度の資料不足を課題扱いしない。
- 将来の再開は利用者見込みとして扱い、2027／2028の開催を確定情報として登録しない。
- 対象バンド：3.5・7・21・50・144・430・1200MHz。免許された全モード。
- 規約の条件下でレピーター・ネット経由も可。コンテスト部門の禁止を流用しない。
- メンバー：レポート＋HAMtte/HMT。一般：レポート＋都道府県番号（北海道01）。
- `5913`なら59と13、`59913`なら599と13。名前抽出と混ぜない。
- 全角半角・英大小・かなの違いを吸収し、`HMT / HAMUTTE / HAMTTE / はむって / ハムッテ`等を判定候補にする。
- FT8も実際に自由文交換している。FT8だけ判定対象外にしない。
- メンバー判定は交換内容から初期設定し、交信別チェックで修正可能にする。
- 規約集計は同一局1日1回。別日なら再び有効。原本行は自動削除しない。
- 20局賞：メンバー10局以上を含む20局。抽選：メンバー5局以上。順位・得点は不要。
- 電子提出はPDFまたはExcel添付。本文にデータだけを貼る形式は不可。このためExcel出力案。
- 先に提示された2023年コンテスト部門は別資料。パーティーに得点3点／1点や本文提出可を持ち込まない。

### 3.3 JAG WARC

- 10・18・24MHz。会員／一般それぞれに電話・電信・デジタル、最大3部門へ別々に提出。
- 一般局同士も有効。会員はレポート＋M、一般はレポートだけ。デジタルは通常交信。
- 一般局の交換番号空欄をエラーにしない。デジタルにMを強制しない。
- JARL様式。会員のコード欄は会員番号、一般は空欄。得点・マルチ不要。
- 10局以上でステッカー。不要ならメールでTXT/CSV提出可。希望時は郵送手続き。
- 同一局・連続・日付違いの判定をソフトで強制しない。SWLの連続受信規定を通常交信へ流用しない。

### 3.4 100周年/ニューカマー＆HAMtte ウェルカム

- 通常HAMtteとは別項目。JARL・JARD共催。
- バンド：3.5・7・21・28・50・144・430・1200MHz。免許された全モード。
- 交換：レポート＋初開局年下2桁＋局種 N/C/W/HN/HC/HW。
- 局種は本人選択。ニューカマー／カムバックの該当する免許年月日はサマリー意見欄。
- W同士は対象外、HWはWと区別。バンドまたは日付違いの同一局交信は有効。
- JARL R1.0/R2.1でサマリー込み出力。Webフォーム再入力を理由にサマリーを省略しない。
- 規約10局以上の記述に対し受付ページは1有効交信から電子参加証。10局未満で出力を止めない。
- クラブ・チャレンジの講習会集計は個人提出とは別で、今回追加する個人ログ機能に混ぜない。

利用者の送信番号は `12HW`。ログにないので一括入力し、各QSOの送信レポートと組み合わせる。

| 相手 | 送信RST | 受信RST | RMKS | 送信交換 | 受信交換 |
|---|---|---|---|---|---|
| JL1HCD | 59 | 51 | 433.16 25C | 5912HW | 5125C |
| JF1NVP/1 | 57 | 57 | 433.16 25C | 5712HW | 5725C |
| JK1MWD | 59 | 58 | 433.16 93HC BURO | 5912HW | 5893HC |
| 7L2NGD | 59 | 59 | 433.16 92HW | 5912HW | 5992HW |

`06W`等の先頭ゼロを保持。RMKS末尾固定で抽出しない。周波数・QSLタグを交換内容へ混ぜない。

## 4. アワード共通設計

利用者の理想：アワード選択 → 自局コールと期間（初期値は全期間） → 条件に適した候補 → 確認・差し替え → 所定リスト。

- 通常の時系列LOGに限らない。QSLカードリスト、累計表、局名一覧などを対象ごとに作る。
- アワードごとに独立した実績DBを持つ。内部処理は共有する。保存技術の選択は未確定で、原本TXTを別DBへ置換する話ではない。
- 特記なし／特記付きの実績を区別する。同じ系列のJCC200→300は積み上げ。
- 申請候補・提出済み・認定済みを区別。ファイル作成だけで申請済みにしない。訂正可能。
- 既得段階・発行番号・使用した地域等を保存。発行番号のない賞も扱えるようにする。
- QSL受領はRMKSの `BURO.R / hQSL.R / eQSL.R / CARD.R` 等の既存タグを参照。単なるBUROは受領済みではない。タグの正式な一覧は既存実装と照合する。
- 通常のJARL規程は紙と電子QSLを認め、所持は自己宣誓。カード画像の登録を必須にしない。
- アワードごとのQSL要否・条件を持たせる。100周年には受領フィルターを強制しない。
- 同じコールを一律除外しない。AJDは実運用エリア、JCCは交信時の市。移動により同じ基本コールでも別地域へ使える。
- 市郡区の変更前の記録を変更後へ勝手に置換しない。基準日・地域の履歴を保持。
- 通常JARLでは同一免許人の複数個人コール合算可。社団局を混ぜない。特別アワードには個別規約・Q&Aを適用。

### 過去実績の登録

- CSV/TXT取込、地域番号の改行・カンマ区切り貼付、一覧チェック。
- 元のQSOがなくても市郡番号等だけで登録可能。架空QSOを原本へ作らない。
- JCC200取得という件数だけの登録も可能だが、使用市不明では追加分の自動照合が完成しないことを表示。
- **逆方式：残りのJCC/JCG番号を貼り付ける。** 残り以外を達成済みとして扱う前に基準一覧・件数を確認。
- 「残り」が未交信・QSL未受領・未申請のどれかを区別する案。詳細UIは今後具体化。
- 補集合は本人申告実績として保存し、QSL受領の事実を捏造しない。

### 通常JARLアワードの対象

AJD、WAJA、JCC、JCG、WACA、WAGA、WAKU、AJA、ADXA/ADXA-HALF、WASA-HF/V・U・SHF、WARC各バンドとWARC-1000、50/144/430MHz各賞、V・U-1000、1200MHz以上の掲載バンド賞、135/475kHz、アマチュア衛星「ふじ」、JARL Stations各賞を今回確認した通常アワード群とする。

SWL版・HACは一覧に存在するが、既存PSLogのSWL対象外方針を今回の一覧紹介だけで覆す実装承認とは扱わない。必要なら対象範囲を明示して別途整理する。

### 特記

最大3つ。周波数、モード（CW/SSB/FM/AM/Digital等）、QRP/QRPp、同一都道府県・エリア・スクエアを主な対象とする案。特殊なSatellite/EME等も記録と手動選択を可能にし、すべての自動判定に固執しない。

QRPは5W以下、QRPpは0.5W以下。原本にない電力を推測しない。AJAの周波数特記不可など明示条件は定義に持つ。FT8を通常アワードで一律FT8特記として出すのではなく、個別規約に合わせる。

## 5. 通常カードリスト・AJA様式

利用者提供の原本は変更せず保持する。利用者は古い様式の不足や誤記を補ってよいとの方針。

| ファイル | 確認内容 |
|---|---|
| JARL_AW_E2-0506.xls | QSLカードリスト。C～H列に地域番号・コール・日付・バンド・モード・備考。C6から6列TSV貼付案 |
| Total- record-list.xls | バンド別に市・郡・区・合計を集計する累計記録表 |
| AJA-list_202401.xls | AJA-Listは3428行44列。地域×バンドにモード・コール・日付・確認欄。累計記録表も含む |

- AJA内部DBは `地域番号 / バンド / 相手コール / 交信日 / モード / QSL受領 / 申請履歴` 等の一覧。
- 出力時に所定の行・列へ配置。利用者に巨大なマトリクスを直接操作させない。
- 地域×バンド、区と市の数え分け、過去申請との照合が重要。AJA計数の詳細は規約に沿って今後実装前に確定する。
- 記入済み旧AJA表の取込も検討対象。
- 提供様式には135/475kHz列不足、一部バンド見出しの欠落・誤記らしきものがある。位置や誤記の文字だけに依存しない。
- 通常リストはコピー／TSV出力が基本案。AJAは表への配置出力と累計表を作る。実際の保存形式・レイアウトは実装時に具体化する。
- JCC等の上位申請では既得発行番号を記載すれば旧リスト省略可。追加分と累計の整合を維持。

## 6. 特別アワード3系統

### 6.1 JARL創立・アマチュア無線100周年

- QSL不要、交信だけで申請。2026-06-01～2027-09-30の対象期間。
- 自局の国内外・移動範囲制限なし。ネット経由・レピーターも認める。
- J賞＝10プリフィックス、A賞＝10市区、R賞＝10郡、L賞＝10都道府県。
- 100/1000賞は同じ局でも別バンドを計数。10000賞はバンド・モード違いでも1局。
- 100 AJD銅銀金、100 WAJA銅銀金、イベント局賞は記念運用局の指定と種別を照合する必要がある。単なる8J/8N全局を対象にしない。
- 申請書＋リスト。公式Q&AではExcel一体様式を推奨。各賞に応じて並び順を変える。
- 同じQSOを別の賞に使用可能。特記は最大3、FT8/RTTYの個別表記や自由特記等も個別規約に従う。
- 発行番号なし。一般アワードDBの番号必須制約を設けない。

### 6.2 全日本10,000局

- 2500/5000/7500/10000段階。QSL必須。最上位へ直接申請も可。
- 原則同じ相手はバンド・モード・移動地点・サフィックス違いでも1局。免許人違いの同一コールは証明付きの例外。
- 日本国内陸上からの申請交信、相手も陸上。クロスバンド・レピーター・衛星等は対象外。
- 専用申請書、47都道府県リスト、交信局リスト、コールエリア別累計表。
- 47都道府県リストは1枚1バンド、各県1局。段階ごと累計3/6/9/12枚。全リストで異なる局。同バンド最大4枚。
- 10000段階は各エリア5～15%の条件。Q&Aの範囲に従い下位段階へ勝手に拡張しない。
- 特記SINGLE MODE、段階途中の変更不可。本人指定を保持する。

### 6.3 全世界10,000局

- 2500/5000/7500/10000段階。QSL必須。相手の同一局計数・陸上等は専用規約に従う。
- 段階別必要エンティティ100/130/160/200、ITUゾーン40/50/60/70、六大州＋南極。
- **日本の局は日本本土・小笠原・南鳥島・南極各1局、最大4局**（Q&A）。国内多数局で達成させない。
- 専用申請書、交信局リスト、ITUゾーン・六大州南極リスト、ARRLエンティティリスト。
- 元の交信局リストから各補助リストを選出。使用目的の○△□等の印を相互反映。
- SINGLE MODE / SINGLE BAND / ALL ZONE特記。途中変更不可。ALL ZONEはQ&A記載の75陸上ゾーン。
- 移動先エンティティ・ITUの個別扱い・無効期間はQ&Aも参照。通常の国名推定をそのまま確定扱いしない。

### 全日本・全世界の出力と人の手続き

- 審査者2名の証明。Q&Aは全リスト自筆署名を指定。署名をソフトで作成・代行しない。
- メール提出は署名済み一式PDF。ソフトは整形・署名欄まで用意し、確認と署名は人が行う。
- ページ当たり件数の変更は認められる。ページ間の一貫性・照合のしやすさを保つ。
- 一般の自己宣誓のみという規則で、この特別な審査条件を消さない。
