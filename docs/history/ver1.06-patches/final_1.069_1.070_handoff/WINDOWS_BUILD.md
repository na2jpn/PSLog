# Windows配布準備 — PSLog 1.069

## 基本手順

1. Ver1.068 PATCH08 + FIX1適用済みソースへPATCH09を適用したVer1.069ソースを用意する。
2. `python -m unittest discover -v` を実行し、Windows/PySide6を含む全テストが通ることを確認する。
3. `./build-windows.ps1` を実行する。
4. `dist/pslog/pslog.exe` と `dist/pslog/exec/PSLogUpdater.exe` が生成される。
5. `pslog.exe --update-self-check` が自動実行され、更新モジュール読み込みに失敗した場合は配布ZIPを作らず停止する。
6. `release/PSLog_1.069_Windows_<timestamp>.zip` が生成される。

## 配布ZIP

Windows版ZIPは新規導入とVer1.043以降のアップデートで共通です。

- 新規・手動入替: `PSLog_1.069_Windows_<timestamp>.zip` を展開する。
- アップデート: 同じZIPを「ヘルプ → PSLogをバージョンアップ」で、展開せずそのまま指定する。

利用者の `config/`, `logbook/`, `bak/`, `output/` は配布ZIPに含めず、アップデートでも保持します。

## 配布フォルダー

```text
PSLog\
 ├─ pslog.exe
 ├─ _internal\
 ├─ exec\
 │   └─ PSLogUpdater.exe
 ├─ meta\
 │   ├─ BUILD_INFO.json
 │   └─ PSLOG_UPDATE_INFO.json
 └─ docs\
```

ルート直下の通常ファイルは `pslog.exe` のみです。

### Ver1.061 PATCH 01 重点確認

- 通常エクスポート/POTA/SOTA/コンテスト/QSOパーティー/アワードで、開始・終了の片側だけ、日付8桁だけ、両方空欄がそれぞれ正しく動くこと。終了 `20260917` はその日の末尾まで含むこと。
- コンテストの確認事項が赤字タイトル `確認事項（全て確認して要チェック）` の枠内に表示され、項目なしの大会では枠ごと出ないこと。ネット/クラスター/ログソフト等の除外対象文言が確認チェックとして出ないこと。
- 参加部門の `選択…` を押した時、現在の局種・実運用電力で候補が絞られ、現在部門が有効ならその部門が選択済みで表示されること。
- Ver1.06へUpdaterで上げた環境に古いオール岡山公式ルールが残っている場合、1.061初回起動で不要な固定運用OPPLACE必須が解消されること。
- 未変更の公式ルールは新しい同梱版へ更新されること。公式ルールを手編集したものは保持され `（ユーザー変更）`、独自ルールは `（ユーザー定義）` と一覧表示されること。

### OPPLACE（運用地）最終確認

- 移動運用を指定した場合、または提出コールが `/1`, `/JD1`, `/P` 等なら、運用地なしで提出できないこと。
- 固定/常置場所運用では、大会側が常時必須としていない限り運用地を強制しないこと。
- 現行登録で常時必須を維持する4大会（オール千葉、オール兵庫、KCJ、KCJトップバンド）は、固定運用でも運用地必須のままであること。

### Ver1.065 PATCH 05 重点確認

- QSL受領一括処理の「今回の受領方法」は初期値が `選択してください` で、方式を明示選択するまで読み込み・照合へ進めないこと。

### Ver1.069 PATCH 09 重点確認
