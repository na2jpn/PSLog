## 修正内容

QSL一括受領「処理の詳細」の候補選択方式を、実際のhQSL運用に合わせて修正しました。

- 複数候補はラジオボタンではなくチェックボックスで表示します。
- 同じ入力TXT行から複数QSOを選択できます。1枚のhQSLが複数QSOを確認している場合、該当QSOをすべて選択できます。
- 一意一致は従来どおり初期チェック済みです。
- 複数候補は初期チェックなしで、人間が必要なQSOを1件または複数件選択します。
- 未一致でも、入力時刻±3分に存在するQSOを「手動候補」として表示し、チェックして割り当てられます。
- これにより、メール側が `JH6JRN`、PSLog側が `JH6JRN/6` のような移動表記違いでも、人間判断で `/6` のQSOへ受領を割り当てられます。
- プリフィックス・エリア数字・サフィックス違いなども、±3分内のQSOであれば手動候補として確認できます。
- ±3分内に候補がない遠隔の未一致は選択できず、未処理として残ります。
- 同一PSLog QSOを別の入力行から重複選択した場合は、既存の重複防止を維持します。
- 1入力行から複数QSOを処理しても、結果レポート／未処理TXTの入力件数・残件判定が崩れないよう集計を調整しました。

## Windows側確認

1. `python -m unittest discover -v`
2. JL7AIAのように1入力行から複数QSO候補が出るケースで、候補がすべてチェックボックスになることを確認。
3. 同じ入力行の2候補を両方チェックできることを確認。
4. `JH6JRN` → `JH6JRN/6` のような移動表記違いが、手動候補としてチェック可能になることを確認。
5. 361分差のように±3分内に候補がない未一致は、選択できず未処理として残ることを確認。
6. 複数選択したQSOすべてに指定の受領方法が反映され、結果TXT末尾のPSLog原本行にも複数行が記録されることを確認。
