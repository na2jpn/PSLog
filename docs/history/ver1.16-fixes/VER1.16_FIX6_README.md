## 修正内容

### Windowsでの一時的なファイルロックに対する保存リトライ

Windowsでログ保存時に、ウイルス対策ソフト、インデクサー、同期・動画編集関連ソフト等が一瞬だけ対象ファイルを開いた場合、`os.replace()` が `PermissionError / WinError 5 / WinError 32` になることがあります。

FIX6では、既存ファイルを原子的に置き換える処理に短時間のリトライを追加しました。

- 最大5回試行します（初回 + 4回リトライ）。
- 待機時間は 50ms → 100ms → 200ms → 400ms です。
- 各リトライ前に元ファイルの内容を再確認します。
- 待機中に別ソフトが実際にログ内容を書き換えた場合は、従来どおり外部変更として保存を停止します。
- 永続的な権限不足は握りつぶさず、最終試行後に従来どおりエラーとして通知します。
- 一時ファイルは成功・失敗どちらの場合も後始末します。

今回Windowsテストで発生した以下のような一時ロックを想定した修正です。

```text
PermissionError: [WinError 5] アクセスが拒否されました
...\.pslog-xxxx.tmp -> ...\logbook\2026_....txt
```

テストを削除・緩和する対応ではなく、PSLog本体の保存処理をWindows上でより堅牢にしています。
