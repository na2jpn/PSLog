# PSLog Ver1.16 FIX7

適用先: PSLog Ver1.16 + FIX1～FIX6 適用済み環境

## 修正内容

### 仮想COM作成処理を再設計

- com0com の作成処理を、外部ソフト用・PSLog内部用の**両方を通常のCOMポートとして作る**方式へ変更しました。
- 物理COM8の場合、基本候補は `COM208 ⇔ COM209` です。
- どちらかが使用中なら、`COM308 ⇔ COM309`、`COM408 ⇔ COM409` のように100ずつ上げます。
- `setupc.exe` の `install PortName=COM# PortName=COM#` を管理者権限で実行し、作成されたpair IDを同じ管理者プロセス内で取得します。
- 作成後に両端へ `RealPortName` を設定し、WindowsのCOM一覧へ両方が現れるまで最大15秒確認してからPSLogの状態ファイルへ保存します。
- `setupc.exe` 自体を「管理者として実行」に設定している場合でも、通常権限の `setupc list` に依存せず作成できるようにしました。
- Windows側で一時的にデバイス登録が遅れても、即座に「未作成」へ戻らないようにしました。
- 作成・削除は引き続きUACが必要ですが、通常の無線機接続・中継開始ではUACを要求しません。

### 無線機設定と仮想COM設定を分離

設定画面を以下のタブ構成に整理しました。

- 入力補助
- 無線機設定
- 仮想COM中継
- バックアップ

「無線機設定」では、無線機・COM・通信速度・接続テスト・接続／切断を先に操作できます。
仮想COMを使用しない利用者は「仮想COM中継」タブを設定する必要はありません。

「仮想COM中継」タブにも接続／切断ボタンを配置しています。これは無線機設定タブと同じ接続状態を操作します。

## 以前のFIX5/FIX6で作成を試した場合

以前の試作処理がWindows上へCOMポートを残している場合、その番号は使用中として避けます。
たとえばCOM208が既に存在する場合、FIX7ではCOM308/COM309を選ぶ場合があります。

## 確認ポイント

1. 無線機を切断する。
2. 設定 → 無線機設定で物理COMが確認できる状態にする。
3. 「仮想COM中継」タブを開く。
4. 「仮想COMを作成」を押す。
5. UACを許可する。
6. 状態が `常設：COM208 ⇔ COM209` などへ変わることを確認する。
7. 「仮想COM中継を使用する」をONにし、接続する。
8. 外部ソフトでは左側（例 COM208）を指定する。

Version番号は Ver1.16 のままです。
