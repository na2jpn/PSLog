## 修正内容

### 仮想COM有効時に「接続中…」から進まない問題

無線機の物理CI-V接続と、com0comによる仮想COM準備を分離しました。

- 物理COMで無線機の応答を確認できた時点でPSLogを「接続済み」にします。
- 周波数表示は仮想COMの準備を待たず、物理接続が成功した時点で更新します。
- com0comの仮想ポート生成は別スレッドで行い、物理CI-Vの監視を止めません。
- 仮想COMの生成・開始に失敗しても、無線機との物理接続は維持します。
- 設定画面では「仮想COMを準備中…」または仮想COMだけの失敗理由を表示します。
- メイン画面では周波数表示のツールチップから仮想COMの状態を確認できます。

### com0com処理の停止・残骸対策

- `setupc.exe` の各操作にハードタイムアウトを設け、補助ツールの停止でPSLogが永久待機しないようにしました。
- com0comがペアを作成した直後に一時状態を記録し、その後の処理中にPSLogが終了しても次回起動時に残骸を識別しやすくしました。
- 物理接続側でエラーが起きた場合も、進行中の仮想COM生成をキャンセルして後始末するようにしました。

## 期待するWindows確認

1. 仮想COM OFFで従来どおり無線機へ接続できること。
2. 仮想COM ONで「接続」を押した直後、物理接続が成功すれば周波数表示が緑になり値が表示されること。
3. 仮想COM準備中でも無線機接続が維持されること。
4. com0com側が失敗した場合、物理接続は残り、設定画面に仮想COMだけのエラーが表示されること。
5. 仮想COMが成功した場合、COM208（競合時は+100）等が表示されること。
6. 「切断」およびPSLog終了後にPSLogが作成した仮想COMが削除されること。
