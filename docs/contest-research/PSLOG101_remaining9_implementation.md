# PSLOG101 残り9到達版の実装範囲と確認事項

定義の数は87管理項目を基準とし、残り28から19を進めて9です。競技種目448、ファイル数、工程数は別の数です。PSLOG100の過去の原案・未解決記録は削除していません。

## 元ログと提出用データ

PSLog原本の11列は不変です。CQカントリー識別子、DXCC識別子・大陸、実交換GL、送信系列、部門資格、運用時間は提出作業データとして管理します。通常の国・地域DBをCQ用へ上書きしません。
RS/RST/SNRを交換しない大会の双方空欄を保存できるようにしました。片側だけ空欄は通常の検証対象です。CQ VHF・岡山FT・WW-DIGIの出力にはレポート列を付けません。他のレポート必要大会は実値を確認し、599やSNRを補いません。
採点はすべて「申告得点（審査前）」です。相手の主催提出・照合結果を推測しません。

## 今回の採点と出力

- 埼玉: 28種目、市区町村72コード、クロスモードを電話扱い。相手の通信方式を専用欄で実記録から入力します。
- CQ VHF 2大会: 各12種目。50MHz1点・144MHz2点とGL4マルチ、Roverの自他GL別重複、移動後に元GLへ戻る場合を検証。相手Roverの/R表記を必要とする初期対応です。デジタルはFT4/FT8/MSK144/Q65を検証、他型式は未検証。
- CQ 160 2大会: 各6種目。2/5/10点、MM5点/マルチなし、米本土48州+DC・加14地域・その他CQカントリー。実周波数出力を初期対応とします。
- 奈良: 24種目、開催窓、得点×コール末尾英字数×開局年数を独立積。Multi1/Multi2実値列と実担当者を出力。資料のNX28はPDF画像で照合しました。
- 京都: 32種目。地域マルチと3桁記念局番号を独立加算、年齢・初免許日係数を最後に切上げ。単帯2又はマルチ1、開催8窓を確認。
- CQ WW CW/SSB: 各47種目、2025保存規約。RTTYは2026の41種目。CQカントリー・ゾーン・米加地域を独立集計し、同国0点でも有効なマルチ、MMのゾーンだけの扱いを区別。
- CQ WPX CW/SSB: 各26種目、RTTY23種目。全バンド共通プリフィックス・重複・バンド/大陸別点と、部門ごとの実送信連番系列。番号の再採番をしません。CLASSIC/ROOKIE/YOUTH/TB-WIRESは本体得点と別のオーバーレイ集計・資格として確認します。
- AADX CW/Phone: 各22種目。2026開催日別選択、AS自局はDXCC/非AS自局はWPXプリフィックス、帯域別点とMM例外。最初24運用時間、60分休憩、MSの系列別10分と新マルチ条件。以後や他バンドの交信もCabrilloへ残します。実際の年齢/平均と01を保持。SOJR/SOSVは自局JA又は所在地確認済み日本島嶼IDと実年齢を照合。
- JARL RTTY: 5種目、同大陸2/異大陸3点、MM2点/マルチなし。本土JA/K/VE/VKのコールエリアとその他DXCCを混同しません。末尾のプリフィックス数字、ポータブルエリア、数字なし移動0を扱います。年齢00/99/01、YOUTH資格を分離。JARL R1.0/R2.1 UTCを実装し、YOUTHはAGEと意見欄へ記載。Cabrillo識別子は未確認のため未対応です。
- WW-DIGI: 28種目。FT4/FT8共通重複、GL4中心間の球面距離点とGL2のバンド別マルチ。受信ZZ00は未知のまま保持し、総得点は未確定、CLAIMED-SCOREを省略して出力。画面の点・マルチは既知部分の小計です。ZZ00を0点確定や実在GLに置き換えません。SO/MO送信機区分と毎時8変更を確認。
- 岡山FT: 12種目。GL4のみ、L/H/V別提出、QRP5W、通常/社団SO/MOと特別局チェックログ。利用者のJH1HST/PM95/L-SD/40Wを回帰例にしました。公式案内どおりWSJT-X WW-DIGI形式のCabrillo（DG、UTC、GL、TX列）を生成し、岡山専用フォームでL-SD等の部門を選びます。
- 宮崎: 29種目、KJを市郡へ統合。利用者確定の県人国外は1点・マルチなし。県内国外は6大陸、その他ANは点だけでマルチを創作しません。国外の追加番号空欄は実RSTのみで出力。複数実交信の採用は明示チェックログ指定で選び直せます。AB2帯/混合CW+電話、新人免許日、送信地域、1MB本文出力を確認。

## 日程原典と曖昧さの保持

WPX公式2026 HTMLのSSB見出しは2025と誤記されています。追加保存した公式日本語PDF `sources/wpx_rules_2026_jp_datecheck.pdf` 冒頭は2026年3月28～29日、CW5月30～31日です。これに基づきます。`wpx_home_date_confirmation_2026.html` は取得時には2027開催案内へ更新されており、2026日の証拠には使用しません。
WW-DIGI締切本文は「48時間以内」と「9月1日23:59 UTC」が不一致です。矛盾を解消済みとはせず、早い側での提出を案内します。距離計算は球半径6371.0088km・GL4中心の短経路で、3000km境界における主催計算との同値は未確認です。
AADX原典7(4)はMM局の得点掲載あり・順位付けなしです。旧原案の「掲載なし」を訂正します。自局/MMはアジア相手のみ有効、運用大陸に従う通常のマルチ種別で申告し、主催審査前として扱います。相手/MMはマルチなしです。
宮崎MKJのモード構成は本文未明示です。一般MXAのCW+電話必須を自動拡張せず、未明示記録を残します。古いFAQの一括MOチェックログ条件より現行規約・利用者確定を優先します。

## 入力が必要な実運用情報

AADX/JARL RTTYは通常の「国・地域」作業欄へ一貫したDXCC識別子を入力します。本土JA、K（WもRTTY本土別名として許容）、VE、VK、その他HL/DL等。小笠原はJD1-OGASAWARA、南鳥島はJD1-MINAMITORISHIMAなど別IDにし、大陸を実運用地で確認します。名称や未知IDを推定確定しません。
CQ系は別欄のCQ識別子を使用します。プリフィックスだけで島嶼や大陸を強制判定しません。疑わしい複合コールは確認で停止します。
送信系列は元11列にないため、MS/M2等は実際の役割を別欄で指定。交信時刻だけでは全送信区間や同時波を証明できないので、機械照合と設備・運用の本人確認を分けます。

## 受付確認の限界

全出力はローカル生成・検証で、主催者への送信はしていません。岡山の取得済みフォームとJSでは、受入パーサーはサーバー側のuploadLog.phpです。内部の受入試験を済ませたとはせず、公式のWSJT-X形式との構造照合までです。取込後に内容・UTC選択・正式部門を確認する案内を添えています。
Windows EXE作成・実機確認は引き続き残ります。定義残り9を製品完成や提出受理保証としません。
