# PSLog Ver1.17 検証結果 — 2026-10-19

## 実施結果

- 関連94件（今回追加20件、既存保存・タブ・検索・無線機／仮想COM回帰等）: OK、プロセス終了コード0。
- 全160テストモジュール、計986件を別プロセスで実施: 全モジュールでunittestのOK、FAIL/ERRORなし。
- ただし151モジュールのみ終了コード0。9モジュールはOK出力後、LinuxのQtネイティブ終了処理でSIGSEGV/SIGBUSとなった。従って「全体コマンドが正常終了した」とは扱わない。
- 異常終了9モジュールを未変更のVer1.16正本でも比較: 7モジュールで同じ終了時エラー、2モジュールは今回の比較では正常終了。全9モジュールとも検証項目はOK。同じQt終了時の不安定さが既存正本でも起きている。
- Python338ファイルのcompileによる構文検証: OK。
- Linuxオフスクリーンで左右の番号入力欄とラベルの折返しを確認。日本語Noto Sans CJK JPフォントは検証環境だけに設定し、配布ソースへ追加していない。
- radio_control.pyは利用者提供の1.16正本とバイト一致。DTR/RTSのopen前OFF、Hamlib PTT NONE、常設COM、setupc Working Directory固定を維持。関連回帰テストもOK。

全体テストの一括実行ではQt/PDF処理中・終了時のネイティブ異常も生じたため、最終の全件確認は各モジュールを別プロセスにした。テストの削除・無効化や、異常終了コードを成功扱いする変更はしていない。既存のWindows用tools/run_tests.pyも未変更。

## データ保護の確認

- JH1HSTで1件記録→JH1HST/1で2件目記録→起動中に手動統合→旧ファイル削除→3件目の記録を試行。
- 履歴検索では統合した1件目も認識。書込みは古いSessionの変更検知で停止。
- 入力中の相手コール、相手番号、自分番号、日時が残り、外部で追加した実ファイルをバックアップ。
- 再読込後の明示的な再記録と、4件目・5件目の連続記録で5件すべて残ることを確認。
- 同じサイズ・mtimeの外部変更、外部からの新規ファイル、置換、削除、形式不正、別Repositoryからの記録、バックアップ失敗、最初の確認後の変更、Windows置換リトライ中の変更も確認。
- SET・コンテストタブ切替は外部追加したTXTの内容を書き換えず、再読込して履歴へ反映。
- 標準／EASYの履歴検索でも、起動中の追加・削除を認識。
