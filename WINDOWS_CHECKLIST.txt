[Ver1.16重点 — 無線機]
[ ] 設定に「無線機設定」がある。
[ ] CI-Vで物理COMへ接続し周波数を取得できる。
[ ] Hamlibでrigctldを使用し周波数を取得できる。
[ ] 設定済みなら次回起動時に自動接続する。
[ ] ＋タブ右: 未接続 -.--MHz 薄灰 / 接続 7.012MHz 等 緑。
[ ] 自動セット3チェックは初期OFF。
[ ] 標準: RETURNで選択したRMKS1/RMKS2/Bandだけ反映。MODE不変。
[ ] RMKS周波数は単位なし（例 7.012）＋末尾半角スペース。同値連続RETURNで重複しない。
[ ] EASY: RMKS2が非表示でもチェックONなら保存後のRMKS2に入る。
[ ] コンテスト: RMKS1チェックはOFF固定/無効。RMKS2/Bandは利用可。
[ ] フリラ: RMKS1/RMKS2/Band自動セットは無効。

[Ver1.16重点 — 仮想COM中継]
[ ] 初期OFF。OFF時は仮想COM中継を開始しない。
[ ] com0com未導入/権限不足でも物理無線機接続とPSLog本体は継続使用できる。
[ ] 仮想COM作成/削除時だけUACが出る。通常の接続/切断やPSLog終了ではUAC不要。
[ ] 物理COM8ならCOM208（外部）⇔COM209（PSLog内部）を作成。競合時はCOM308/309、COM408/409…と+100。
[ ] 作成後にPSLogを終了しても仮想COMペアがWindows上へ残り、再起動後UACなしで再利用できる。
[ ] WSJT-Xまたはリグコントロールソフト1本→外部COM→PSLog→無線機でCI-V双方向通信できる。
[ ] 外部ソフトから周波数変更したときPSLog表示も追従する。
[ ] 設定で仮想COM中継をOFFにして接続を組み直せる（PSLog再起動不要）。
[ ] 「仮想COMを削除」でUAC後にPSLog管理ペアだけ削除できる。
[ ] setupc.exeがProgram Files (x86)にある環境でも自動検出/手動指定できる。
[ ] setupc管理者実行でSystem32のcom0com.infを誤参照せず、setupc.exeのフォルダーから作成できる。
[ ] Hamlib選択時は仮想COM中継を使用しない。

[Ver1.16重点 — コンテスト編集]
[ ] FT8等のコンテストログでRST欄に英数字交換情報があっても「交信を編集」で保存できる。
[ ] 同じログをQSL処理画面で補正しても非数値RSTを理由に保存失敗しない。
[ ] 通常ログのFT8新規入力/通常編集では従来の +00 / -12 形式検証が維持される。
